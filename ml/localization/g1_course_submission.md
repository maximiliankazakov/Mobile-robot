# Подпроект G1 для сдачи

Сравнение двух методов локализации TIAGo на Webots R2025a и ROS 2 Jazzy.
Оба метода проходят C++ replay, а метрики и парные интервалы вычисляет
`localization_metrics`. Python используется для подготовки данных и запуска
инструментов. Исходный отчёт из предыдущей серии и первичный реестр сохранены.

## Что входит в комплект

- Отчёт `G1_итоговый_отчёт_к_сдаче.pdf` на 10 страницах.
- Архив `g1_hw1_replay.tar.zst`. В нём 100 парных отложенных эпизодов,
  по 10 маршрутов на каждом из двух вариантов каждого сценария. Исходная
  траектория при пропуске датчика служит контролем того же эпизода.
- Входы и эталон в разных подкаталогах, две обученные модели, train/val-экспорты,
  сохранённые траектории, метрики C++, карты, сценарии, хеши, диагностические
  журналы и команды запуска. Вес B выбран на validation до тестовых запусков.
- [Первичный реестр](capture_plan_g1.csv) и [реестр дополнения](capture_supplement_g1.csv).
  Шесть защитных остановок и два ранних номинальных результата с B v1
  сохранены. В финальную таблицу с B v2 вошли 92 исходные и восемь новых пар.

## Проверка из чистой копии

Нужны x86-64, Docker Compose и образ разработки курса с Ubuntu 24.04 /
ROS 2 Jazzy. Для архива нужен zstd. Проверенный запуск использовал CPU без GPU.
При пользовательском Docker задайте адрес сокета текущего пользователя.

```bash
export DOCKER_HOST="unix:///run/user/$(id -u)/docker.sock"
tar --zstd -xf /path/to/g1_hw1_replay.tar.zst
dataset="$(realpath bundle)"
(cd "$dataset" && sha256sum --quiet -c SHA256SUMS)
docker compose --profile dev build dev

# Новый C++ replay всех 100 эпизодов с контрольными вариантами и абляцией.
bash integration/g1_v1/evaluate_course.sh "$dataset" ./g1-full --jobs 4

# Быстрый пересчёт по сохранённым траекториям тем же C++ оценщиком.
G1_EVALUATION_MODE=archived bash integration/g1_v1/evaluate_course.sh \
  "$dataset" ./g1-archived --jobs 3

# Пример повторения одного физического сценария.
bash integration/g1_v1/evaluate_course.sh "$dataset" ./g1-slip \
  --case g1-test_0-slip-extra-00
```

Каждому новому replay нужен отдельный каталог результатов. Сборка G1 и replay
изолированы от сети. Эталон монтируется только для расчёта метрик. Интерфейс
replay сверяет SHA-256 входов и моделей. На нашей машине полный повтор вместе
со сборкой занял менее пяти минут; время зависит от CPU. Используйте
`G1_COURSE_IMAGE`, чтобы указать уже собранный образ разработки курса.

Итоги лежат в `results/summary.json`, метрики отдельных прогонов в
`results/per-episode.json`. Данные для графиков содержат ATE, RPE, курс,
p95, NIS/NEES, частоту принятия, fallback, потери, восстановление и профиль
времени ядра. Профиль задержек зависит от загрузки компьютера. На полном
повторе ошибка положения воспроизвелась для всех методов и условий.
Комплект показывает отличия в миллиметрах, первичные значения C++ в метрах.

## Проверка на защите

1. Выбрать один эпизод и показать, что оба метода использовали ту же карту,
   временные метки и начальную позу.
2. Показать изменение ковариации B при успешном ICP и объяснить, почему при
   вырожденном ICP обе реализации используют прогноз.
3. По `source-series` разобрать три сохранённых близких возврата LiDAR
   и объяснить разницу между защитной остановкой и оценкой ошибки G1.
4. Подтвердить фактический личный вклад по [шаблону](../../templates/CONTRIBUTION.md).
   Личная защита и демонстрация общей миссии относятся к регламенту курса.

Карты в складских сценариях построены SLAM. Карты двух коридоров построены
из геометрии и проверены по реальным для Webots сканам. Диагностика
складских сеток использует грубые независимые прямоугольные маски, поэтому
показатель IoU привязан к этому приближению и совместно известной области.
