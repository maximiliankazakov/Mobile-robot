# Train_0: воспроизводимая оценка классического метода

[Контракт оценки](train0_sealed_scoring_contract.json) проверяется командой
`sha256sum -c train0_sealed_scoring_contract.sha256` из этого каталога.
Манифест фиксирует исходную запись, её независимую валидацию и артефакты
Docker-воспроизведения. Исходный Compose завершился с кодом 1; проверка
неизменённой записи и последующий replay/score завершились с кодом 0.
Это один пробный эпизод, не обучающие данные, не зачётный A/B.

GT записан с ROS-меткой `map`, но его числа относятся к Webots world.
Только офлайн-оценщик переводит их в замороженную систему карты:
`x_map=x_world+8 м, y_map=y_world, yaw_map=yaw_world`. Сдвиг задан
по расположению старта и проверен отдельно, не подобран по траектории.
Инференс получает только входную запись. Входы до 23,088 с нужны для
запуска метода; метрики используют только [23,088; 35,868] с.
639 из 639 пар получены интерполяцией, максимальный фактический интервал
GT 20 мс при пределе 40 мс. Основной результат: XY ATE RMSE 7,33 см;
стартовое выравнивание даёт 1,51 см и служит только диагностикой.
RPE XY RMSE за 1 с: 0,85 см (589 окон).

Стартовый сдвиг объясняет существенную часть абсолютной ошибки, не всю.
По сохранённому CSV оценка в начале replay ровно (0, 0), затем до
начала зачётного интервала делает ступени: на первой заметной ступени
(22,720 с) становится примерно (+3,02; +2,51) см, к 23,020 с
(+5,08; +4,23) см. В первой оцениваемой паре ошибка примерно
(+5,07; +4,23) см, в последней (+4,24; +6,67) см. Это наблюдение
по существующим данным, а не установленная причина сдвига.

## Диагностика старта по той же записи

На Apparat оба прогона завершились в Ubuntu 24.04 / ROS 2 Jazzy в
пользовательском Docker без сети. Использованы неизменённый входной bag из
контракта оценки, одна начальная поза (0, 0, 0) и одна замороженная карта.
В первом прогоне поданы все входы, во втором исключена публикация
`/sensors/scan`. Ground truth и команды в контейнер не передавались.
Трассировка добавлена только во временную копию исходников. Логика фильтра
и параметры методов сохранены.

| Время скана, с | Время публикации поправки, с | XY после коррекции, см | NIS | Средняя потеря Huber до → после ICP, 10⁻³ м² |
|---:|---:|---:|---:|---:|
| 22,700 | 22,720 | (+3,02; +2,51) | 1,728 | 2,157 → 0,547 |
| 22,800 | 22,820 | (+4,12; +3,39) | 0,463 | 0,915 → 0,526 |
| 22,900 | 22,920 | (+4,75; +3,92) | 0,213 | 0,699 → 0,544 |
| 23,000 | 23,020 | (+5,08; +4,23) | 0,075 | 0,593 → 0,534 |

Для каждой строки стоимость обеих поз посчитана на одних и тех же
326 соответствиях финальной итерации. Поворот и перенос публикуются на
следующей отметке одометрии, через 20 мс. В 23 общих отсчётах до 23,088 с
колёсно-инерциальная одометрия совпала по XY между прогонами. В контроле
глобальная поза оставалась у нуля. С LiDAR разница с контролем к 23,080 с
достигла 6,61 см.

На этой записи начальную ступень дают принятые обновления scan-to-map.
ICP уменьшает потерю относительно той же карты, поэтому это наблюдение
само по себе не различает особенности карты, экструзику LiDAR и выбор
соответствий. Для такого различения нужна отдельная проверка геометрии
на независимых ориентирах. Данные остаются пробными и не входят в
обучение или зачётное сравнение A/B.

Локальные артефакты: `train0-startup.a9oKxFHj`. В каталоге сохранены
обе траектории, журнал первых поправок, скрипт повтора и SHA-256.
Сводка `verified-startup.json` имеет SHA-256 `09ff04f3d86ea4d51e11fe8f52b60b946acbdd276ab119513fe0c79d421457bc`.

## Сравнение с геометрией сцены

Скрипт [diagnose_train0_geometry.py](diagnose_train0_geometry.py) читает четыре
неподвижных скана из того же SQLite bag. Геометрия берётся из запечатанного
`train_0.wbt` и размеров `RectangleArena.proto` и `WarehouseRack.proto`.
Луч переносится через записанный `base_link → lidar_link` при исходной позе
(0, 0, 0). Лучи выбираются по пересечению с заданным ориентиром и отступу
от его краёв. Поза EKF, GT и подгонка к карте не используются.

Сравнение по нормали к поверхности. Плюс означает смещение в свободную
сторону. Числа в таблице — медианы, в сантиметрах. Для каждого направления
повторяются те же лучи в четырёх сканах.

| Ориентир | Разных лучей | Скан − сцена | Карта − сцена |
|---|---:|---:|---:|
| Северный участок западной стены | 21 | −0,91 | +5,10 |
| Южный участок западной стены | 21 | −0,92 | +10,10 |
| Западная грань северной стойки стеллажа 2 | 5 | +0,11 | +0,44 |
| Северная грань южной стойки стеллажа 2 | 3 | −0,18 | +3,92 |
| Западная грань южной стойки стеллажа 2 | 4 | +0,17 | Не найдена |

Грань карты считается найденной, если она параллельна ориентиру, смотрит
в ту же сторону, попадает на ту же координату вдоль грани и находится
в пределах 0,22 м по нормали. Это отдельная геометрическая проверка,
а не повтор выбора соответствий ICP.

Два участка одной прямой стены в карте различаются по положению на
одну ячейку (5 см), хотя медианы проекций сканов почти одинаковы.
На измеренных участках смещение контура карты больше расхождения
сырого скана со сценой и имеет тот же знак по X, что и поправка ICP.
Наблюдение указывает на вклад локальной геометрии замороженной карты.
Эти ориентиры не определяют полный вклад экструзики, соответствий
и структур карты по Y. Результат не используется для настройки EKF,
ICP, калибровки или MLP по этому пробному эпизоду.

Для воспроизведения из корня Capstone нужны каталог `inputs` именно из
`hw1-train0-odom-capture.9IRYFIrQ`, исходный `train_0.wbt` из
`hw1-train0-slam.EiJSzlu1` и ранее собранный образ `capstone-dev:local`.

```bash
export DOCKER_HOST="unix:///run/user/$(id -u)/docker.sock"
bag=/absolute/path/to/hw1-train0-odom-capture.9IRYFIrQ/inputs
world=/absolute/path/to/hw1-train0-slam.EiJSzlu1/train_0.wbt
out="$(mktemp -d)"
timeout -k 4s 30s docker run --rm --network none --pull never \
  --mount "type=bind,src=$PWD/ml/localization,dst=/code,readonly" \
  --mount "type=bind,src=$bag,dst=/bag,readonly" \
  --mount "type=bind,src=$world,dst=/train_0.wbt,readonly" \
  --mount "type=bind,src=$out,dst=/out" --entrypoint /bin/bash capstone-dev:local -c \
  'source /opt/ros/jazzy/setup.bash && python3 /code/diagnose_train0_geometry.py /bag /train_0.wbt /out'
```

Локальный артефакт `train0-geometry.SAGATdlJ` содержит JSON, CSV по лучам,
версию образа, SHA скрипта и контрольные суммы. Независимый повтор дал
тот же побайтный CSV.

## Проверка вклада двух участков западной стены

В нативный C++ replay подали одну и ту же замороженную сетку, четыре
стартовых скана и 23 колёсных отсчёта с записанной IMU. Исходная ветка
повторила четыре поправки ROS replay с максимальной разницей
(2 \times 10^{-8}) по вектору (x, y, yaw). Во временной копии
`estimator.cpp` перемещали только восточные грани occupied/free
на выбранных участках западной стены в её известную плоскость x = −2 м.
Сохранились исходные входы, ковариация и настройки отбора. Изменение граней
может менять выбор ближайших соответствий, как и изменение контура карты.

| Временное изменение в replay | Граней перемещено | X, см | Y, см | Модуль сдвига, см |
|---|---:|---:|---:|---:|
| Исходные грани | 0 | 5,08 | 4,23 | 6,61 |
| Северный участок | 17 | 4,41 | 4,23 | 6,11 |
| Южный участок | 17 | 4,32 | 4,27 | 6,08 |
| Оба участка | 34 | 3,73 | 4,10 | 5,54 |

В каждом варианте приняты все четыре скана. Перенос обеих групп уменьшил
модуль сдвига на 1,06 см (16,1%), преимущественно по X.
Оставшийся сдвиг 5,54 см требует проверки других участков карты
и соответствий. Это вмешательство проверяет вклад двух участков
на одной записи и не является предложением править сдаваемую карту,
экструзику или параметры по результатам пилота.

Артефакты в `train0-wall-counterfactual.At3ftwc6`: исходные события,
четыре CSV, вмешательство для временной сборки, `summary.json` и SHA-256.
