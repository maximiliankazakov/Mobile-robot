# Train_0: воспроизводимая оценка классического метода

[Контракт оценки](train0_sealed_scoring_contract.json) проверяется командой
`sha256sum -c train0_sealed_scoring_contract.sha256` из этого каталога.
Манифест фиксирует исходную запись, её независимую валидацию и артефакты
Docker-воспроизведения. Исходный Compose завершился с кодом 1; проверка
неизменённой записи и последующий replay/score завершились с кодом 0.
Это один пробный эпизод, не обучающие данные, не зачётный A/B.

GT записан с ROS-меткой `map`, но его числа относятся к Webots world.
Только офлайн-оценщик переводит их в замороженную систему карты:
`x_map=x_world+8 м, y_map=y_world, yaw_map=yaw_world`. Сдвиг задан
по расположению старта и проверен отдельно, не подобран по траектории.
Инференс получает только входную запись. Входы до 23,088 с нужны для
запуска метода; метрики используют только [23,088; 35,868] с.
639 из 639 пар получены интерполяцией, максимальный фактический интервал
GT 20 мс при пределе 40 мс. Основной результат: XY ATE RMSE 7,33 см;
стартовое выравнивание даёт 1,51 см и служит только диагностикой.
RPE XY RMSE за 1 с: 0,85 см (589 окон).

Стартовый сдвиг объясняет существенную часть абсолютной ошибки, не всю.
По сохранённому CSV оценка в начале replay ровно (0, 0), затем до
начала зачётного интервала делает ступени: на первой заметной ступени
(22,720 с) становится примерно (+3,02; +2,51) см, к 23,020 с
(+5,08; +4,23) см. В первой оцениваемой паре ошибка примерно
(+5,07; +4,23) см, в последней (+4,24; +6,67) см. Это наблюдение
по существующим данным, а не установленная причина сдвига.

## Диагностика старта по той же записи

На Apparat оба прогона завершились в Ubuntu 24.04 / ROS 2 Jazzy в
пользовательском Docker без сети. Использованы неизменённый входной bag из
контракта оценки, одна начальная поза (0, 0, 0) и одна замороженная карта.
В первом прогоне поданы все входы, во втором исключена публикация
`/sensors/scan`. Ground truth и команды в контейнер не передавались.
Трассировка добавлена только во временную копию исходников. Логика фильтра
и параметры методов сохранены.

| Время скана, с | Время публикации поправки, с | XY после коррекции, см | NIS | Средняя потеря Huber до → после ICP, 10⁻³ м² |
|---:|---:|---:|---:|---:|
| 22,700 | 22,720 | (+3,02; +2,51) | 1,728 | 2,157 → 0,547 |
| 22,800 | 22,820 | (+4,12; +3,39) | 0,463 | 0,915 → 0,526 |
| 22,900 | 22,920 | (+4,75; +3,92) | 0,213 | 0,699 → 0,544 |
| 23,000 | 23,020 | (+5,08; +4,23) | 0,075 | 0,593 → 0,534 |

Для каждой строки стоимость обеих поз посчитана на одних и тех же
326 соответствиях финальной итерации. Поворот и перенос публикуются на
следующей отметке одометрии, через 20 мс. В 23 общих отсчётах до 23,088 с
колёсно-инерциальная одометрия совпала по XY между прогонами. В контроле
глобальная поза оставалась у нуля. С LiDAR разница с контролем к 23,080 с
достигла 6,61 см.

На этой записи начальную ступень дают принятые обновления scan-to-map.
ICP уменьшает потерю относительно той же карты, поэтому это наблюдение
само по себе не различает особенности карты, экструзику LiDAR и выбор
соответствий. Для такого различения нужна отдельная проверка геометрии
на независимых ориентирах. Данные остаются пробными и не входят в
обучение или зачётное сравнение A/B.

Локальные артефакты: `train0-startup.a9oKxFHj`. В каталоге сохранены
обе траектории, журнал первых поправок, скрипт повтора и SHA-256.
Сводка `verified-startup.json` имеет SHA-256 `09ff04f3d86ea4d51e11fe8f52b60b946acbdd276ab119513fe0c79d421457bc`.
